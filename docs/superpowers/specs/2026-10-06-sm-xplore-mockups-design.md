# SM-Xplore Mockups Design

## Scope

- Convert the 16 existing wireframes from pages 02, 03, and 04 into high-fidelity desktop mockups.
- Create pages 06, 07, and 08 in Figma, one per feature:
  - 06 - Mockups - Gestionar Actividades
  - 07 - Mockups - Gestionar Eventos
  - 08 - Mockups - Gestionar Resenas
- Preserve the wireframe information architecture, content, states, actors, use-case labels, and actions.
- Do not create prototype connections or mobile variants.

## Visual Direction

- Caribbean tourism identity for Santa Marta.
- Deep Caribbean navy: `#12304A`.
- Lagoon teal: `#0E8C8A`.
- Seafoam: `#DDF3EC`.
- Sand: `#F4EBDD`.
- Coral: `#F47C5A`.
- Ink: `#12212B`.
- Use Manrope for the interface and DM Serif Display sparingly for public tourist headings.
- Use a subtle teal wave/route accent only where it does not alter the wireframe structure.
- Keep management screens more restrained than tourist-facing screens.

## Images

- Find visual references per destination or subject while designing.
- Use references as mockup visuals, not as final licensed production assets.
- Keep image placement, crop intent, and count aligned with each wireframe placeholder.
- Do not invent additional image slots or content.

## Fidelity Rules

- Use 1440x900 as the desktop reference size, while making every mockup responsive and auto-adjustable.
- Preserve existing screen names and UC/US traceability.
- Apply visual styling, components, spacing refinement, states, and imagery only.
- Keep loading, empty, error, availability, publication, and response states represented where present.
- Build layouts with Figma Auto Layout, constraints, fill-container/hug-content behavior, and min/max limits where appropriate.
- Avoid hardcoded coordinates for normal content; use absolute positioning only for intentional overlays, badges, and floating elements.
- Keep headers, navigation, cards, forms, tables, filters, and action groups aligned when the frame width changes.
- Use consistent spacing tokens, alignment anchors, and responsive wrapping so text and controls do not overlap.

## Validation

- Verify every new page contains the same number of screens as its source page.
- Compare representative mockups against their wireframes for structure and content.
- Check alignment, spacing, contrast, component consistency, and image crops.
- Resize representative screens from the 1440px reference width and verify that content reflows without overlap or clipped controls.
- Verify that repeated components use shared Auto Layout behavior instead of independent manual positioning.
- Export or document final mockup captures after visual verification.
